# TDD ループ

対象は [.claude/rules/common/testing.md](../../rules/common/testing.md) に定める「ゲームロジックの純粋関数」。描画/UIコードには適用しない。

## ループ

1. **Red — 失敗するテストを書く**
   - これから実装する振る舞いを1つだけ選ぶ（例: 「縦方向に相手石を1つ挟んだら反転する」）。
   - 対象モジュールの `*.test.js` に、その振る舞いを検証するテストケースを1つ追加する。
   - テストを実行し、失敗すること（対象関数が未実装、または期待通りでないこと）を確認する。

2. **Green — 最小実装でテストを通す**
   - そのテスト1つを通すために必要な最小限のコードを書く。先回りして他のケースまで実装しない。
   - テストを実行し、全テストが通ることを確認する。

3. **Refactor — 整理する**
   - 重複や読みにくさがあれば、テストが通ったままの状態でコードを整理する（[JSスタイルガイド](../../rules/javascript/style-guide.md)に従う）。
   - リファクタ後も全テストが通ることを再確認する。

4. **コミットする**
   - この1振る舞い分の実装が完了したら、[atomic-commit](../atomic-commit/SKILL.md) スキルに従って `test`/`feat`/`fix` いずれか適切な type でコミットする（テストと実装を1コミットにまとめてよい）。

5. **次の振る舞いへ**
   - 1へ戻り、次の未実装ケース（境界値、盤端、複数方向同時反転など）に進む。

## 3D反転ロジックに適用する場合の観点

[othello-3d-flip-rule](../othello-3d-flip-rule/SKILL.md) のアルゴリズムに沿って、以下の順でケースを積み上げるとループが回しやすい:

1. 1方向・隣接1マスだけ相手石があり、その先に自分の石があるケース（反転する）
2. 隣接マスが空、または盤外（反転しない）
3. 隣接マスに自分の石（挟めない・反転しない）
4. 同一平面の複数方向で同時に反転するケース
5. 上下方向・斜め方向（層をまたぐ）のケース
6. 盤端・層端での境界値ケース
